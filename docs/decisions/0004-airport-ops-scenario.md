# 0004 需求场景选机场运行监控，并引入航段累积快照

- 日期：2026-10-16
- 状态：已采纳

## 背景

第一版是一个"全球航班统计"式的看板：去重飞机数、国家占比、平均高度。它能跑，但没有使用方，
也就没有可验证的时效要求。要写 SLA，必须先有一个具体的人在具体时刻做具体决定。

## 备选方案

1. **继续做统计报表**：指标好算，但没有实时性需求，不需要流式。
2. **做航班追踪**：需要航班计划数据，OpenSky 不提供。
3. **机场运行监控**：一个值班员在 30 秒内看到机场周边的进近、起降和应急情况——有明确的使用方、
   明确的时效、明确的错误代价。

## 决定

以苏黎世机场（ZRH）运行控制中心为模拟使用方，定义 7 个核心问题（进近架数、小时起降、航段状态、
应急代码、异常航迹、数据新鲜度、数据完整性），每个问题落到一张表和一个指标口径上。
为此新增两张表：起降事件和航段累积快照。

## 代价与风险

- 机场级指标依赖"最近机场"归属和采集范围，口径比全局统计复杂，需要单测和抽查（见 requirements 的验收方式）。
- 航段是累积快照，要处理乱序、超时和重放，比纯追加表复杂得多；M2 的验收记录里能看到为此做的三次修正。
